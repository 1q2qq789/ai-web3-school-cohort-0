─ AI 基础 ─
LLM

大语言模型

Large Language Model

通过互联网级文本训练的语言生成模型，核心能力是 next token prediction — 预测下一个最可能的 token 来生成文本。不是"理解"，而是"统计推断"。

  • 训练数据决定知识边界
  • temperature 控制输出随机性
  • max_tokens 限制输出长度
  • 不擅长精确计算和实时信息
    • Prompt

    提示词工程

    Prompt Engineering

    通过设计输入文本引导 LLM 输出的技术。包括角色设定、上下文注入、few-shot 示例、chain-of-thought 等策略。

  • 好的 prompt 能大幅提升输出质量
  • system prompt + user message 双层结构
  • AI 输出必须验证，不盲信
    • Workflow

    工作流

    Workflow

    多步骤编排的任务流程，每个步骤调用 LLM 或工具，步骤之间传递状态。典型如：资料收集 → 分析 → 生成 → 验证。

  • 确定性的步骤执行
  • 中间结果可查看、可干预
  • 比纯 prompt 更可靠但缺乏自主性
    • Agent

    智能体

    AI Agent

    能感知环境、自主决策、调用工具的 AI 系统。核心组件：LLM（大脑）+ 工具（手） + 记忆（笔记本）+ 规划（日程表）。Hermes 就是 Agent 的典型实现。

  • Agent ≠ Chatbot — 区别在自主执行
  • 需要护栏（人工确认、权限限制）
  • Skills = Agent 的可复用经验
    • Tool Use

    工具调用

    Function Calling

    Agent 调用外部工具的能力：读文件、执行代码、搜索网页、调用 API。Hermes 的 MCP 协议让 Agent 可以接入 100+ 工具。

  • 工具扩展了 Agent 的能力边界
  • 每次调用应有日志和结果验证
    • AI Coding

    AI 编程工具

    AI Coding

    Claude Code / Codex / Hermes 等让 AI 直接操作代码库的工具。价值：快速原型、代码补全、重构辅助。限制：上下文窗口有限、不能完全理解架构意图。

  • 生成 ≠ 理解——输出仍需人工 review
  • 适合任务明确、边界清晰的代码
    • ─ Web3 基础 ─
    Account

    账户与地址

    Account & Address

    区块链的基本单位。EOA（外部账户）由私钥控制，地址是公钥的哈希。钱包不是"账号"，而是私钥管理器+安全责任入口。

  • 助记词 → 私钥 → 地址（单向推导）
  • 地址不是匿名，是假名
  • Agent 不应直接接触私钥/助记词
    • Wallet

    钱包

    Wallet

    管理私钥、签名交易、连接 dApp 的工具。MetaMask 是最流行的浏览器钱包。涉及签名、授权、转账时必须人工确认。

  • 助记词和私钥不能泄露
  • 签名 ≠ 登录——是在授权具体动作
    • Transaction

    交易与签名

    Transaction & Signature

    签名是"授权一个具体动作"，不是"点一下确认"。交易包含：from/to/value/data/nonce/gas limit。签完名发到链上由矿工/验证者打包。

  • 每笔交易有明确意图和成本
  • 签名前务必确认全部字段
    • Gas

    Gas 与执行成本

    Gas & Fees

    链上执行的计算资源定价。Gas = gasUsed × gasPrice。L1 贵但安全，L2 便宜但依赖 L1 安全。失败交易也要付 Gas。

  • Gas 不是手续费，是计算资源定价
  • L1/L2 在执行成本上差异巨大
    • Smart Contract

    智能合约

    Smart Contract

    部署在链上的可执行代码。与普通后端的差异：状态公开、执行公开、部分不可更改。部署在测试网学习和实验。

  • 状态公开执行公开
  • 升级权限可检查
  • 先在测试网练手
    • Testnet

    测试网与区块浏览器

    Testnet & Block Explorer

    Sepolia / Goerli 等测试网用测试币免费交互。区块浏览器（Etherscan）查看交易哈希、状态、Gas、区块高度，形成完整反馈链。

  • 学习实验先在测试网完成
  • 区块浏览器是链上行为的"日志"
    • ─ AI × Web3 交叉 ─
    交叉实验

    AI → 链上执行链路

    AI to On-chain Workflow

    把 AI 输出与链上执行串起来：AI 生成合约交互脚本 → 人工复核 → 钱包确认签名 → 链上执行 → 浏览器验证。

  • 每个步骤必须有明确的边界
  • 签名/转账/写入必须人工确认
  • 失败恢复和日志记录不可少
    • Agent x Wallet

    Agent 与钱包安全

    Agent-Wallet Security

    AI Agent 不应直接接触私钥/助记词。Account Abstraction（ERC-4337）让 Agent 在有限权限下执行操作，比如 Session Key + 每日限额。

  • 私钥必须 Agent-proof
  • AA 是关键基础设施
