### 模块 A｜AI 基础：从 LLM 到 Agent Workflow
- LLM 基本工作方式：概率生成，擅长理解/代码/推理，不擅长事实记忆/确定性计算
- 四个控制层：上下文窗口(工作内存) → 系统指令(身份/边界) → 提示词(任务意图) → 工具调用(做事)
- API 调用入门：model、messages、temperature、max_tokens
- Prompt → Workflow → Agent 边界：决策在人 vs 预定义流程 vs 自主规划
- AI Coding 工具价值与限制：加速原型但不能替代代码审查/架构决策
- AI 输出为什么必须验证：事实错误、引用错误、推理漂移、执行越权、工具误用
- Agent 核心技术组件：State、Memory、MCP、Skills、Tool Calling、Tracing、Guardrails、Handoff、错误恢复

### 模块 B｜Web3 基础：从账户到合约
- 账户/地址/钱包关系：钱包不是普通账号，是私钥 + 安全责任 + 链上动作入口
- 签名不是"点一下确认"，是授权具体动作
- Gas 是计算资源定价不是手续费
- 主网 vs 测试网：先测试网后主网
- 区块浏览器、钱包提示、交易回执构成完整反馈链

### 模块 C｜最小交叉实验
- 链路：AI 生成 → 人工复核 → 钱包确认 → 链上执行 → 区块浏览器验证

## Handbook 阅读

- 章节：[LLM](https://aiweb3.school/zh/handbook/ai/llm/) | [Agent](https://aiweb3.school/zh/handbook/ai/agent/) | [Wallet](https://aiweb3.school/zh/handbook/web3/wallet/) | [Agent Workflow](https://aiweb3.school/zh/handbook/bridge/agent-workflow/) | [Web3 Tool Use](https://aiweb3.school/zh/handbook/bridge/web3-tool-use/)
- 关键概念：
  - **LLM 第一性原理**：模型输出是候选结果，不是事实本身 → 概率合理 ≠ 天然可信
  - **Agent 第一性原理**：Agent 不是自主权，是被约束的执行循环 — 目标、工具、状态、权限、停止条件缺一不可
  - **Wallet 第一性原理**：钱包管理的是链上控制权，不是"账号资料"
  - **Agent Workflow 核心**：把概率模型放进确定性流程里 — 显式流程 + 可恢复状态 + 可回放评估
  - **Web3 Tool Use 核心**：模型可以选择工具，但工具必须用确定性边界限制模型 — 读写分离、参数结构化、日志不可省
